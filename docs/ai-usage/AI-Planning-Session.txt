  A few decisions go beyond what you specified, so check these before you hand
  it off:

  - New shared/ package next to backend/ and frontend/. It holds the types and
    the engine. Both apps import it as TypeScript source, so there's no build
    step.
  - Kickoff step ("Phase 0"). The backend session first sets up the project and
    copies the shared types file word for word from the doc, then commits to
    main before the frontend session starts. After that the types file is
    frozen, and each session only writes in its own folders.
  - The frontend never runs game rules. The server sends the legal moves with
    every state update, and each analyzed move includes the board before and
    after it. The frontend only imports types and a notation helper.
  - Every eval is in "discs" from Black's point of view. The engine scores every
    legal move at each turn, not just the best one, so it can measure exactly
    how much worse the move actually played was. Blunder cut-offs are in discs
    too. They are starting values, meant to be tuned when you integrate.
  - Seat tokens live in sessionStorage, not localStorage. A refresh keeps your
    seat, and two tabs in the same browser can play each other, which makes it
    easier for a reviewer to demo.
  - Passes are automatic. The server inserts a pass whenever a player has no
    legal move, so clients never send one.
  - Coaching tags field. Each analyzed move has a list of simple tags such as
    "took corner" or "allowed corner". It can ship empty if the backend runs out
    of time, and the frontend shows the tags only when they're there.

  The doc also covers the database schema, REST endpoints and socket events, the
  time-estimated task split, a cut/roadmap table, and a short list of risks.
  Playing against the AI is the top roadmap item, because it's about 45 minutes
  of work once the engine exists.

  The biggest risk is analysis speed. A plain JavaScript engine searching 6
  moves deep might take a few seconds per turn. The doc has the backend time one
  real game early and fall back to a per-move time limit or a shallower search
  if it's too slow.
